1. BACKGROUND
Cascade Freight Technologies operates Meridian TMS, the company's core Transportation
Management System, which brokers freight shipments between shippers and a network of
contracted carriers. Rate quotes are currently generated by RateEngine v1, a service
maintained by the Pricing & Rates Team. In Q4 2025, Customer Success logged 412 support
tickets in Helix (the company's ticketing system) related to rate quote errors, with the
two most common root causes being stale lane pricing (error code RATE-409) and invalid
lane definitions (error code RATE-422). Carrier Relations has also flagged that
CarrierConnect API timeouts (error code CARR-503) during rate lookups cause RateEngine to
fall back to cached rates older than the 15-minute freshness threshold defined in the
Rate Dispute Resolution Policy (RDP-002).

2. BUSINESS OBJECTIVE
Reduce rate-related support tickets by 60% within two quarters of launch and bring
RateEngine's p95 quote-response latency to under 2 seconds, in line with the Platform
Engineering SLA commitments described in System Documentation SD-TMS-014.

3. SCOPE
In scope:
- Replacement of the RateEngine v1 lane-pricing cache with a write-through cache backed
  by BillingCore's rate ledger.
- New real-time carrier capacity check via CarrierConnect API v3 (see API-CC-003) prior
  to quote issuance.
- Automated flag-and-hold for any quote where the source lane data is older than 15
  minutes, per RDP-002 section 4.2, routed to Pricing & Rates for manual review.
- Integration with Meridian TMS's Shipment Booking Workflow (WF-SB-01) at the "Rate
  Confirmation" step.

Out of scope:
- Changes to BillingCore's invoicing logic (owned by Billing Operations).
- Changes to CustomerPortal's quote display UI (owned by Customer Success), except for
  new error-code messaging described in Section 5.

4. STAKEHOLDERS
- Pricing & Rates Team (Marcus Webb) — business owner, defines rate logic.
- Platform Engineering (Sarah Chen) — builds and operates RateEngine and CarrierConnect
  API.
- Carrier Relations (Priya Nair) — provides carrier capacity data feeds.
- Customer Success (Diego Ramirez) — handles downstream support impact via Helix.
- Billing Operations (Aisha Thompson) — owns the rate ledger RateEngine v2 will read
  from.

5. FUNCTIONAL REQUIREMENTS
FR-1: RateEngine v2 must call CarrierConnect API v3 endpoint
      GET /v3/carriers/{carrier_id}/capacity before returning a bindable quote.
FR-2: If CarrierConnect API returns CARR-503 or CARR-401, RateEngine v2 must return
      RATE-409 to the caller rather than silently serving a stale cached rate.
FR-3: Any quote flagged RATE-409 or RATE-422 must auto-create a Helix ticket assigned
      to Pricing & Rates, per the Rate Dispute Resolution SOP (SOP-RDR-02).
FR-4: RateEngine v2 must emit a rate_quote_issued event to the shared event bus so
      Meridian TMS can advance the shipment in Shipment Booking Workflow (WF-SB-01).
FR-5: Quote data older than 15 minutes must never be served without the hold flag,
      per RDP-002.

6. NON-FUNCTIONAL REQUIREMENTS
NFR-1: p95 latency under 2 seconds, p99 under 4 seconds (see SD-TMS-014 SLA table).
NFR-2: 99.9% availability, matching CarrierConnect API's published SLA (API-CC-003).
NFR-3: All rate ledger reads must be logged for 2 years per the Data Retention Policy
       referenced in SD-TMS-014 Appendix B.

7. DEPENDENCIES AND RISKS
- Dependency on CarrierConnect API v3 general availability (Platform Engineering
  roadmap, target 2026-03-01).
- Risk: Carrier Relations' carrier onboarding backlog (see Policy COB-001) may leave
  some carriers without capacity data, forcing RateEngine v2 to fall back to FR-2
  behavior more often than projected.
